## Who can call Phase 2 GET verbs

ADR-0001 grants `assets.read` / `scans.read` / `findings.read` / `evidence.read` to **Admin | Analyst | Operator | Auditor**. **Owner** (org creator; not inviteable) already has every action.

So a token bound to any of those five roles can run the Phase 2 GET verbs below. That is **not** Admin-only anymore at the token layer.

| Command | OpenAPI path | Scope | Owner | Admin | Analyst | Operator | Auditor |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `nemesis findings list` | `GET /api/control-plane/findings` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis findings get <id>` | `GET /api/control-plane/findings/{id}` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis findings export` | `GET /api/control-plane/findings/export` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis findings export-xml` | `GET /api/control-plane/findings/export/xml` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis findings export-superusers` | `GET /api/control-plane/findings/export/superusers` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis findings export-shared-suspects` | `GET /api/control-plane/findings/export/shared-suspects` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis findings export-key-locations` | `GET /api/control-plane/findings/export/key-locations` | `findings.read` | yes | yes | yes | yes | yes |
| `nemesis assets list` | `GET /api/control-plane/assets` | `assets.read` | yes | yes | yes | yes | yes |
| `nemesis jobs list` | `GET /api/control-plane/jobs` | `scans.read` | yes | yes | yes | yes | yes |
| `nemesis jobs get <id>` | `GET /api/control-plane/jobs/{id}` | `scans.read` | yes | yes | yes | yes | yes |

`findings export` is the POA&M CSV. Console CKL / CKLB download is a different path: [Export CKL](/first-scan/export-ckl). Spec: portal [`docs/openapi-control-plane-v0.yaml`](https://github.com/Nemesis-Technologies/portal/blob/92ead6425283b0f453c546bddee9d5107503afb9/docs/openapi-control-plane-v0.yaml) at `92ead642`.

401 / 403 fail closed. The CLI does not verify role client-side (no OpenAPI role-GET). Bind the token to the member you intend.

## Not in this CLI

These actions exist on the console (and, for mint, the Admin API). They are **not** `nemesis` verbs. Do not invent `nemesis scan start` or a waiver CLI.

| Action | Owner | Admin | Analyst | Operator | Auditor | Where it lives |
| --- | --- | --- | --- | --- | --- | --- |
| Mint / list / revoke `nms_` tokens | yes | yes | no | no | no | Settings UI or Admin API. Hangs on `settings.manage`. **Not a CLI verb.** |
| Run / cancel scans | yes | yes | yes | yes | **no** | Console **Run Scan**. CLI has no StartScan. |
| Change waivers | yes | yes | yes | no | **no** | Console waiver overlay. CLI has no waiver verb. |
| Register / edit assets | yes | yes | yes | yes | no | Console **Assets**. CLI lists only. |

**Auditor still cannot run scans or change waivers.** The CLI does not expose those verbs, so an Auditor-bound token cannot do them here either. If a later write verb appears, ADR-0001 still denies Auditor `scans.run` / `waivers.change`.

## How you mint a role token

Admin or Owner (`settings.manage`) mints in the console: org **Settings** (portal `[id]/settings`). Pick the target org member (Admin | Analyst | Operator | Auditor, or Owner already on the org). The plaintext `nms_` is shown **once**. List and revoke are on that same panel.

Cite: portal [`apps/cloud/app/(protected)/[id]/settings/api-token-settings.tsx`](https://github.com/Nemesis-Technologies/portal/blob/4b09e04755372c4924cd0f54fc1dfdd79ca55349/apps/cloud/app/(protected)/[id]/settings/api-token-settings.tsx) (NMS-207 / ADR-0072). Admin API mint/list/revoke is the existing `/api/control-plane/tokens` surface (NMS-211). Analyst / Operator / Auditor cannot mint or revoke.

Use that `nms_` with `NEMESIS_PORTAL_URL` + `NEMESIS_API_TOKEN` as the README shows. Never log it. Never send it to `db_scan_engine`.

## Token locks

- Prefix is control-plane **`nms_` only**. Worker prefixes (`nmlw_` / `nmsp_` / `nmdp_`) are a different family. The CLI rejects them fail-closed.
- Never send `nms_` to the engine. Never a DSN. Cloud plane never `StartScan`.
- Authz follows **live** `cp_membership.role`, not a frozen-at-mint role language.
- **CUI never.** Not production-ready. No FedRAMP, CMMC PASS, or certified claims.
