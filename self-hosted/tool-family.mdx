Four names. They are **not** the same binary. Do not rebrand `dbscanner` or `dam-proxy` as “the Nemesis CLI.”

<Warning>
  The product CLI (`nemesis`, repo [`nemesis-cli`](https://github.com/Nemesis-Technologies/nemesis-cli)) is **shipped**: Phase 1 wraps the lab / air-gap / license scripts; Phase 2 is a **GET-only** portal client (`findings` / `assets` / `jobs`). It shipped Admin-only ([NMS-209](https://linear.app/nemesistech/issue/NMS-209/build-nemesis-cli-phase-2-admin-portal-api-scan-findings-evidence)). **Role tokens now exist** (Settings UI mint [NMS-207](https://linear.app/nemesistech/issue/NMS-207/role-based-api-tokens-matching-portal-rbac-ui-mint); Admin API mint [NMS-211](https://linear.app/nemesistech/issue/NMS-211/nms-207-residual-admin-api-mint-for-role-based-nms-tokens)). Phase 2 GET verbs work for Analyst / Operator / Auditor / Owner tokens that have the ADR-0001 reads — not Admin-only at the token layer. The CLI still has **no StartScan and no writes**. See [CLI command × role](/self-hosted/cli-roles).
</Warning>

## What you must not do

- Do not treat `dbscanner` as the customer operator tool.
- Do not treat `dam-proxy` as a CLI shell.
- Do not invent per-offering CLIs (Discovery / Mimic / …).
- Do not invent `nemesis scan start` or waiver writes. [NMS-206](https://linear.app/nemesistech/issue/NMS-206/future-operators-control-dbscanners-via-portal-ui-andor-cli) is not this CLI.
- Do not send `nms_` to the engine. The CLI rejects `nmlw_` / `nmsp_` / `nmdp_`.
- Do not claim Hub-pull compose is air-gap.
